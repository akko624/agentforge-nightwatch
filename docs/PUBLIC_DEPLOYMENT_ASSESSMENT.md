# 验证报告公共访问、存储与成本评估

核验日期：2026-11-03。对象为当前 SQSP 仓库，不是通用 Agent 托管平台。本次只完成方案评估与本地页面实现，未创建公共站点、未购买服务、未把用户工件或现有数据库发布到外部。

文中美元价格均为 USD、税前；免费额度受账户、产品条款、地区和后续调整约束。官方公布费率、工程估算与尚未核验的能力分别标明。工期按熟悉当前代码的一名工程师、每人日约8小时估算，是从本轮优化前 MVP 出发的方案总工作量参考，**不是本轮完成后的剩余工期**，也不是上线承诺。

## 1. 建议与选择顺序

**当前最合适的是“本地可信静态扫描 + 静态报告查看器”。** 把漂亮、可交互的看板作为独立前端部署；用户在浏览器选择已有 JSON 报告，只在内存读取。这样能最快获得公共页面，且不要求服务器保存用户上传文件。它展示已有报告，不会重新执行 ZIP 扫描，也不会证明用户提供 JSON 的真实性。

如果要让收件人打开链接就看到同一份报告，必须让报告数据以某种方式抵达收件人。可公开的脱敏快照可以跟静态站点一起托管；敏感报告则应由有访问控制和过期机制的服务提供。**公共页面地址、本地文件查看器、某份报告的共享地址是三件不同的事。**

本轮已实现两种静态交付：独立本地 JSON 查看器，以及 `scripts/build_report_site.py` 生成的聚合摘要站点包。后者可让同一链接直接显示同份统计摘要；文件包已经能在本地生成，但尚未上传托管平台。签名、账户授权、到期和撤销服务仍未实现。

本轮实际交付物为 `release/sqsp-report-dashboard`、`release/sqsp-report-dashboard.zip`（内置固定聚合摘要）与 `release/sqsp-report-viewer`（仅查看器）。前端33/33测试、两种构建、后端206项测试及Ruff均通过，另有1项真实Redis集成跳过。Edge已验证平台看板和本机HTTP静态摘要页面；没有测试公网/账户匿名可达/手机视口。具体设计和验证范围见[报告设计与实现](REPORT_DESIGN.md)。

只有确认需要“任意用户在线上传 ZIP、离开后再回来、跨设备历史、后台排队和团队协作”时，再上线完整后端。当前低流量下，保存文件的费用通常很小；真正增加成本的是后端常驻进程、访问控制、反滥用和运维。无需因存储单价而立即放弃网站，也不必为只读报告承担整套 SaaS 成本。

| 已有实现 | 对上线的含义 |
|---|---|

特别注意：把现有六服务迁到云平台并不意味着已经完成公共服务化。扫描列表、报告与版本接口都需要基于真实身份授权，防止不同用户读取其他人的工件或报告。

逐文件代码证据、P1/P2事项和查看器输入约束见[公共访问就绪度审查](PUBLIC_READINESS_REVIEW.md)。这些是面向未来不互信公网访客的上线前要求，不表示当前仅监听回环地址的部署已经泄露数据。

## 3. 是否必须有后端存储

| 使用方式 | 是否要运行后端 | 用户数据存储位置 | 能做到什么 | 失去或新增的工作 |
|---|---|---|---|---|
| 本地 JSON 报告查看器 | 不需要 | 当前标签页内存；可由用户另存文件 | 公共前端、本地看板、筛选、打印/导出 | 刷新或关闭后丢失；公共 URL 不包含这份报告；没有新扫描 |
| 脱敏报告静态快照 | 不需要业务 API | 托管平台的静态文件/CDN | 打开链接就能查看同一报告 | 已经发生公开持久化；需审阅脱敏；不能可靠撤回已下载的副本 |
| 浏览器直接扫描 ZIP | 可不需要 | 浏览器内存，或用户明确选择的本地存储 | 理论上可离线进行规范与静态规则分析 | 要重新实现安全 ZIP/YAML/规则和 Python AST 兼容；不能直接复用当前服务端引擎 |
| 后端临时扫描、不保留历史 | 需要计算后端 | 临时内存/磁盘、任务状态，完成后按短 TTL 清理 | 在线上传→计算→下载结果 | 仍有临时存储和隐私责任；请求断开、重试、排队、超时、清理都需处理；不等同零存储 |
| 完整在线平台 | 需要 | 数据库 + 私有对象存储 + 队列 | 历史、对比、后台任务、团队协作、可撤销授权链接 | 需要身份、租户、生命周期、备份、配额、监控与安全维护 |

### 浏览器处理可行，但属于另一种扫描实现

`File`/`FileReader`/Web Worker 可以在客户端读取文件，而不把文件发送给服务器。可优先用在**已有报告 JSON 的展示**。如果改成读 ZIP 扫描，则还需要防 ZIP 炸弹、规范路径/链接/重复条目、安全 YAML、编码和二进制盲区，并把当前 Python AST 检测迁移为受支持的浏览器解析器或 WASM/Pyodide 方案。

Web Worker 可避免阻塞 UI，但不是执行恶意 Skill 的安全沙箱。Pyodide 也不能被当作自动授权执行上传代码的理由。客户端扫描器必须坚持只解析；不使用 `eval`、动态导入上传 JS、执行上传 Python 或把内容注入 HTML。手机浏览器的内存上限、WebAssembly 启动成本、后台标签被终止和依赖下载都需要单独验收。未达到规则等价前应标记为另一引擎，不能沿用服务端的覆盖和测试结论。

`localStorage` 不适合 ZIP/大报告；IndexedDB 可以保留设备内历史，但仍是持久化且可能被清理，也不能自动提供跨设备链接。默认只用内存更容易解释数据边界；要保存到设备时应让用户明确选择。

### 4.2 Sites 的适配边界

本机当前 Sites 1.1.2 插件能力文档明确：静态构建产物可登记到托管 manifest；服务端代码运行于 Cloudflare Workers，每 isolate 128 MB，外部连接通过 HTTP，不能使用 raw TCP。公开 Sites 可接收没有身份 header 的匿名请求，私有 Sites 要求身份；新 Site 默认私有。D1 与 R2 可由平台配置绑定，未用的绑定可以不启用。

这些是**当前插件文档的能力说明**，不是已部署实测结果。此次未建立 Site，未核验账号配额、价格或匿名可达性。Sites 的费用不能直接等同于用户自行开通 Cloudflare 账户的账单；如选此路线，需要确认该账号实际产品权益。公开展示只需要静态 UI；若要跨用户保存报告，应明确引入身份/授权和数据存储。

当前 FastAPI/SQLAlchemy/PostgreSQL/RQ 组合不能原封不动搬入这个 Worker 环境。Cloudflare 本身有 Python Workers，但其 WebAssembly/Pyodide 运行机制不同于普通 Linux CPython 进程；128 MB 包含堆和 WASM 内存。现有最多100 MiB解压数据还会产生拷贝、字符串和 AST，对该限额没有安全余量。见[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)与[Python Workers 机制](https://developers.cloudflare.com/workers/languages/python/how-python-workers-work/)。因此适合先托管看板，扫描计算留在受控 Python 服务。

本机核验资料为 Sites 插件目录下 `SKILL.md`、`references/storage.md`、`references/identity-and-secrets.md`；它们不构成公开的价格承诺。

### 最快的静态上线操作路径

本轮提供独立报告构建入口，避免将依赖扫描后端的完整工作台当作静态产品发布。从仓库根目录执行：

```powershell
Set-Location frontend
npm ci
npm run build:report
# 静态产物：frontend/dist-report
```

`vite.report.config.ts` 使用单独的 `report-site` 入口、相对资源路径、`publicDir: false`，输出 `dist-report`。独立入口不连接扫描后端、不轮询health/API；页面CSP设为 `connect-src 'none'`，因此常规HTTP请求连接被禁止。它仍需要加载本站的JS/CSS等静态资源，不能称为“浏览器完全没有网络”。常规 `npm run build` 仍构建完整平台，两个产物的用途不同。

构建之后，从仓库根目录把已有完整报告或查看器下载的聚合摘要打包到**尚不存在的新目录**：

```powershell
Set-Location ..
.\.venv\Scripts\python.exe scripts/build_report_site.py --report "C:\path\report.json" --output release\public-report-20261103
# 仅发布查看器、不内置任何报告时省略 --report：
.\.venv\Scripts\python.exe scripts/build_report_site.py --output release\viewer-20261103
```

脚本以字段允许列表重新构造 `sqsp-public-1.0` 聚合摘要，保留实际风险指数、severity/category/rule计数、阶段状态/耗时及质量原值；不复制原名、ID、hash、文件路径、证据、context、权限、日志或任意reason，也暂不披露规则集/策略版本。未知分类只映射为固定的“other”，不回显源文本。摘要嵌入 `index.html` 的 `application/json` 数据段，HTML特殊字符转义，不作为可执行脚本。报告仍未经签名，**统计本身也可能透露业务特征，发布前需人工确认愿意披露**。

脚本只复制限定的构建资源并生成 `_headers`；输出目录必须不存在，拒绝与构建目录重叠，永不覆盖已有目录，不上传、不自动发布。先检查新release目录，确认其中没有原始ZIP、完整私有报告、`.env`或日志，再在本机预览：

```powershell
.\.venv\Scripts\python.exe -m http.server 4173 --bind 127.0.0.1 --directory release\public-report-20261103
# 浏览器打开 http://127.0.0.1:4173/
```

静态预览应验证摘要自动出现、导入/筛选和空值状态正确，并通过网络面板确认没有报告外发请求。Python静态服务器不会应用托管平台的 `_headers` 文件；页面meta CSP仍在，生产站点应再次验证实际响应头。

Cloudflare Pages最快可以采用官方Direct Upload：在用户自己的账户新建项目、上传检查过的 `release/public-report-20261103` 或 `release/viewer-20261103` 目录、取得其分配的 `pages.dev` 地址，再用未登录的新浏览器验证。**上传release产物，不上传整个仓库或扫描数据库。** Netlify也可以上传同类静态站点包，额度需按其credits计量。选择Sites时登记该静态产物并走其原生发布流程；若要匿名公共访问，应显式选择公开受众并测试，而不是把默认私有发布当成公共链接。

不带 `--report` 的包只提供查看器，访问者仍需自己选择本地JSON；带 `--report` 的包已内置经过允许列表投影的同一聚合摘要，无需另建数据库即可直接展示。具有身份、到期/撤销和签名的私有分享仍需额外后端服务。此次没有替用户注册项目、发布文件或变更访问权限。部署后的最终验收应记录实际公共URL、匿名访问、浏览器网络请求、内容边界与回滚方式。

已生成的 `release/sqsp-report-dashboard.zip` 为288,809 bytes（约282 KiB），可作为Cloudflare/Netlify直接上传或Sites静态入口准备材料；JS合计gzip约287.6kB，仍保留共享chunk大于500kB的构建提示。这个包内置的统计尚未经可信签名，上传前仍应人工复核是否愿意公开；文件包生成和本机HTTP验证不等于完成公网发布。

## 5. 存储与计算成本模型

### 5.1 本次用于估算的规模

假设每月1000次扫描，平均 ZIP 2 MiB、JSON报告0.2 MiB，保留30天，最多同时收到5个提交；这些是**预算假设，非实测吞吐**。保留原 ZIP 与报告的稳定期空间约为：

```text
ZIP：1000 × 2 MiB = 2000 MiB ≈ 1.95 GiB ≈ 2.10 GB
报告：1000 × 0.2 MiB = 200 MiB ≈ 0.195 GiB ≈ 0.210 GB
合计：2200 MiB ≈ 2.15 GiB ≈ 2.31 GB
再留一份等量备份：约4.61 GB，另加数据库、索引、日志与构建产物。
```

按滚动30天保留的稳定期估算；首月逐日增长时平均占用会更小。数据库大小需要按实际 findings 数量与 JSON 冗余测量，不能把原始ZIP平均体积直接当作数据库容量。当前报告同时在数据库和工件存储保留，不能漏算这份冗余。

R2 Standard 公布每月10 GB-month、100万 Class A、1000万 Class B 免费额度，超额存储 $0.015/GB-month，A类操作 $4.50/百万、B类 $0.36/百万，公网出流量不计费；按账户剩余额度和产品计费单位计算。本模型2.31GB及少量读写可能落在免费额度内；**不代表所有账户一定为零，也不包含其他计算服务账单**。即使不使用免费额度，纯存储数学值 `2.31 × $0.015 ≈ $0.035/月` 也说明文件容量不是主要成本，但官方有向上取整等规则，不能把这个小数当作发票。见[R2定价](https://developers.cloudflare.com/r2/pricing/)。

D1 适合新建轻量共享索引/分享权限记录，不能直接替代当前 PostgreSQL 的连接与全部SQL语义。官方免费总存储5GB、每日读500万行/写10万行，付费首5GB后 $0.75/GB-month；是否超限取决于实际索引和查询扫描行数。它不负责扫描计算。见[D1计费](https://developers.cloudflare.com/d1/platform/pricing/)。

### 5.2 方案总成本比较

| 方案 | 月基础设施预算 | 主要工程/维护成本 | 适用结论 |
|---|---|---|---|
| 静态查看器，本地选择报告 | Cloudflare纯静态可为$0；自定义域名另计 | 前端维护、依赖更新；没有用户文件的云存储 | **成本最低的首发路径** |
| 脱敏快照公共托管 | 低流量可在静态免费额度内；Netlify等按部署/带宽计量 | 发布复核、版本/缓存/撤回流程 | 适合产品演示、公开合成报告 |
| 报告分享服务（仅报告，无ZIP） | Worker付费最低$5/月；少量R2/D1可能在免费额度内 | 授权、过期、配额、清理、审计；需额外实现 | 合理预算约$5–15/月作早期预留，**估计而非套餐报价** |
| 完整平台，单台4GiB VM | VM例价$24/月；备份/域名/监控另计 | 运维、安全更新、数据库恢复与单点故障 | 约$30–45/月作早期预算预留；保留现有Compose结构较直接 |
| 完整平台，Render分离服务 | 官方小常驻栈示例$30/月，文件存储、流量、workspace与容量升级另计 | 先实现R2/S3工件适配、身份/租户；省部分主机运维 | 基础预算约$30–60/月起；若要真正5个任务并行或更大内存会明显增加 |
| 本地Skill/可信CLI + 静态查看器 | 可以没有常驻云服务费用 | 宿主订阅/按量模型、设备资源、安装和版本维护、技术支持仍有成本 | **开发者内部使用的优选组合** |

Worker付费最低$5/月及所含请求/CPU量来自[Workers定价](https://developers.cloudflare.com/workers/platform/pricing/)，它只覆盖相关Worker产品计费，不能用来估计整个Python平台。表中的$5–15、$30–45与$30–60均为预留范围，不能与官方最低费率混为一谈；不含税、付费域名、模型、动态沙箱、企业支持和维护工时。

Render官方2026年9月的参考栈为 $7 Web + $7 Worker + $6 PostgreSQL + $10 Key Value = $30/月；2GB Web或Worker的参考价分别为$25/月。此处引用其官方文章的具名示例，**不是当前账号采购锁价**，下单需核验地区、套餐和workspace。见[Render官方成本示例](https://render.com/articles/production-rails-hosting-guide)与[服务类型](https://render.com/docs/service-types)。

**PaaS迁移的关键改造：** Render普通持久盘只能被一个service instance访问，另一服务不能挂载同一盘。当前API写原ZIP、Worker读原ZIP和写报告，因此不能给API和Worker各挂一个同名路径就认为已共享；要实现 `ArtifactStore` 的R2/S3适配，或额外的受控共享存储方案。该适配当前未实现。见[Render磁盘限制](https://render.com/docs/disks)。单VM Compose可保留同机命名卷，仍需独立备份。

五个同时提交可以排队，不等于五个任务同时执行。低流量初期可先允许一个Worker顺序处理，给出等待状态。若Render按五个512MB Worker并行计算，示例基础计算变为 `$7 + 5×$7 + $6 + $10 = $58/月`；若API与五个Worker都升级为其示例2GB档，则为 `$25 + 5×$25 + $6 + $10 = $166/月`。这只是配置算术，尚未证明其吞吐足够；应先对最大归档与恶意边界压测，再确定内存和并发。

### Netlify的一个透明计费例子

假设只托管报告查看器，月生产发布4次、总出站流量1GB、10000资源请求，不调用Functions或模型：`4×15 + 1×20 + 1×2 = 82 credits`，低于Free的300 credits。如果每天都生产发布，单发布项就约450 credits，已超过Free上限。实际资源请求包含JS/CSS和图片，不是只数页面访问；总流量也应包含前端包与报告。免费套餐的硬额度不能视为自动付费保障，需要监控暂停行为。计量依据为前述[Netlify credits文档](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/how-credits-work/)。

## 6. 公共报告与公网上传的安全设计

报告公开之前应采用**字段允许列表的专用快照格式**。现有凭据脱敏只能匹配部分已知模式，不能保证业务名称、目录名、owner标签、说明正文、内部URL、源代码片段和策略配置没有敏感信息。UI折叠、隐藏栏目或前端路由守卫都不能保护已放进JSON/HTML的内容。

| 对象 | 建议发布/访问方式 |
|---|---|
| 原始ZIP、脚本、附件 | 私有；不出现在静态站点源码、公开bucket或公共CDN目录 |
| 本轮公开报告快照 | 仅含允许列表内的实际风险指数、severity/category/rule计数、阶段状态/耗时、文件数、质量原值和固定枚举；原名/ID/hash/路径/证据/context/权限/日志/reason均省略，规则集和策略版本也不披露 |
| 用户私有报告 | 服务端校验所有权/租户；不依赖不可猜测UUID作为唯一授权 |
| 分享链接 | 分离scan_id与高熵token；服务端保存token摘要、范围、有效期与撤销状态；短期缓存并支持过期；不把token放分析埋点 |
| 报告可信度 | 本地导入JSON显示“读取已有报告，未重新扫描/未验证来源”；需要可信证明时增加可信服务端签名与公钥校验，不能把文件hash当签名 |

静态公共快照可以更新或下架源文件，却不能可靠撤回已下载、截图或被缓存的副本。需要严格到期/撤销的业务，应选择授权服务而不是永久公开JSON。`noindex` 只能影响配合的搜索引擎，不是权限控制。URL fragment虽然一般不随HTTP请求发送，也可能进入浏览器历史、同步、截图和复制记录；不建议把完整敏感报告或原始文件编码进公共链接。

如果开放ZIP上传，需要在当前边界上补：真实身份与逐资源授权、用户/租户配额、速率与并发控制、队列长度上限、总存储上限、扫描/对象生命周期和TTL、去重对象引用计数、备份恢复演练、跨用户隔离测试，以及部署/规则更新时配置签名漂移处理。清理共享对象前需确认没有其他版本引用，不应为降低成本直接删除内容寻址对象。数据库与对象存储保持私有，动态与模型能力继续默认拒绝。

## 7. 转成Skill/插件是否更合适

**可以，建议做“可信SQSP包装Skill调用静态扫描核心”，而不是让Agent直接阅读并遵从待检查Skill的指令。** 包装Skill的职责是收取ZIP路径、调用安装好的受信扫描器、解释结构化结果和输出JSON/HTML；目标归档始终是待检查数据。扫描器仍执行安全解包、YAML/AST、版本化规则与脱敏，不导入、不执行上传脚本。

| 比较项 | 网站 | 本地Skill/可信CLI |
|---|---|---|
| 用户进入门槛 | 链接即可访问，适合非开发用户 | 需要兼容宿主、Python/依赖安装、工具权限和可信版本 |
| 云基础设施 | 完整服务需要计算、数据、队列和运维 | 可取消常驻服务器，使用用户设备资源 |
| 数据边界 | 工件上传至服务方，需保留策略与授权 | 可保持本地，但Agent上下文或遥测仍可能外发；需明确宿主行为 |
| 结果一致性 | 服务统一规则与依赖，便于审计 | 宿主、OS、Python与规则版本可能漂移，需锁依赖与记录来源 |
| 团队/历史/治理 | 易集中管理，但需真正实现租户与身份 | 本地文件可比对；跨用户协作、撤销与集中审计较弱 |
| 安全责任 | 公网反滥用和隔离职责较重 | 宿主Agent可能受目标文本注入；包装边界与工具允许列表仍关键 |
| 能力覆盖 | 当前静态MVP；动态/模型须另接合格基础设施 | 同样只能宣称实际完成的静态覆盖，不因变成Skill而获得沙箱或真实任务评测 |

预计可信CLI提取、包装Skill说明、版本锁定及回归适配约2–5人日；这是工程估计，当前仓库尚未交付可分发的安装器或宿主Skill包。网站现有核心可以复用，不应复制一套漂移规则。静态报告看板与本地Skill并不冲突：开发者本地生成JSON，非开发者用静态查看器打开，是兼顾低成本与表达效果的组合。

Skill不是零成本渠道。宿主订阅、可能的模型调用、设备CPU/内存、依赖安全更新、分发签名与支持成本仍存在。当前确定性扫描无需LLM；若仅为解释报告而调用模型，可以设为可选，不能强制把敏感源代码发给外部模型，也不能用模型口头判断替代实际规则证据。

## 8. 推荐执行路线与验收

| 顺序 | 推荐动作 | 验收方式 |
|---|---|---|
| 本轮实现 | 已提供真实看板、本地JSON查看器和聚合快照打包 | 良性/风险/未运行三类数据正确；错误JSON受限；无自动数据上传；可访问性与小屏布局；实际测试见本轮设计验收记录 |
| 首次公共展示 | 审核生成的release包，再选Cloudflare Pages或经账号确认的Sites发布 | 匿名新浏览器打开；检查公开产物中无原ZIP、私有JSON、日志或配置；聚合统计未经签名且已获作者披露许可 |
| 开发者内部使用 | 评估本地可信CLI/Skill包装 | 只扫描不执行目标；锁定规则/依赖；结果可导入同一看板 |

本报告的建议是先用成本较低的静态报告体验验证分享需求，保留现有Python扫描核心。暂不重写纯前端扫描器，也不为演示直接公开当前无认证API。是否创建公共Site、选择账户、购买套餐或发布具体报告，应作为明确的下一次部署动作执行；此次没有进行这些外部变更。
