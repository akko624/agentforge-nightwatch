# 验证报告公共访问、存储与成本评估

## 结论

最快且最轻量的公共交付不是把扫描平台公网化，而是发布静态报告查看器或审核后的脱敏摘要。它们不需要后端业务服务、数据库或用户账号；静态站点只分发前端资源和明确允许公开的报告摘要。完整扫描平台继续作为本地可信工具运行。

| 目标 | 推荐产物 | 后端 / 存储 | 难度 |
|---|---|---|---|
| 对方自行查看已有报告 | `/viewer` 静态查看器 | 无业务后端；文件仅在浏览器内存 | 低 |
| 发送一个直接打开的链接 | `build_report_site.py` 生成的公开摘要 | 静态托管保存摘要副本 | 低 |
| 在线上传、异步扫描、跨设备历史 | 新的受控在线服务 | 身份、私有对象存储、数据库、配额与审计 | 高 |

静态查看器只渲染用户选择的 JSON；它不重新扫描 ZIP，也不验证报告签名。公开摘要是一个新的允许清单投影，默认不包含名称、ID、路径、hash、证据、权限、日志或原始工件。公开前仍需人工审阅；静态托管不等于可以收回已下载副本。

## 快速上线方式

1. 构建静态报告：`npm run build:report`，或执行 `scripts/build_report_site.py --report ... --output ...`。
2. 将输出目录部署到 Cloudflare Pages、GitHub Pages、Netlify、Vercel 或 Sites 等静态托管。
3. 确保 SPA 路由有回退，发布包不含 `data/`、上传 ZIP、`.env`、私有报告或 source map 中的敏感内容。
4. 访问公网链接，核验匿名可达、响应式布局和浏览器网络面板没有上传 / 外发报告内容。

Cloudflare Pages 与 GitHub Pages 适合公开技术示例和脱敏报告；Vercel / Netlify 适合带预览的前端发布；Sites 是可快速登记静态产物的候选。套餐、地区、账单与公开权限会变化，应在实际账号中确认。当前仓库未替用户创建公共站点，也不把未审阅报告自动发布。

## 是否必须配置后端存储

不必须，取决于产品能力：

- 只分享工具：不存用户报告，浏览器本地内存处理即可。
- 分享同一份脱敏报告：不需要业务数据库，但静态托管会存一份公开摘要。
- 在线扫描但不保留历史：仍需要临时计算和任务状态；“短期保存”不是“无存储”。
- 历史、版本比较、多人协作、可撤销分享：需要受身份与资源权限保护的数据库与对象存储。

把现有 Python 规则直接搬到浏览器并不等于零成本：ZIP / YAML 安全约束、Python AST 规则、脱敏与差异比较都需重新实现和验收。Web Worker 只能避免 UI 卡顿，不是执行不可信 Skill 的安全沙箱；客户端路线同样禁止 `eval`、动态导入或执行上传内容。

## 成本与演进建议

| 方案 | 典型持续成本 | 适合场景 | 主要代价 |
|---|---|---|---|
| 静态查看器 / 摘要 | 通常可从免费静态额度开始 | 作品集、报告分享、技术演示 | 无在线 ZIP 扫描与历史 |
| 本地 SQLite 平台 | 软件成本为零，使用本机资源 | 个人开发、受控演示、Agent 本地调用 | 只能在作者设备上扫描 |
| 受控在线平台 | 常驻计算、对象存储、备份、监控与认证成本 | 有真实多人上传 / 历史需求 | 安全、隐私、运维与滥用防护 |

推荐顺序是先用静态摘要验证分享价值，再根据真实需求决定是否建设受控在线服务。Agent Skill 包装器是连接本地平台的轻量替代：Agent 可在可信本机提交 ZIP 并获得报告，但它不是云端 SaaS，也不会绕过安全边界。
