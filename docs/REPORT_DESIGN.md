# 验证报告看板：设计与实现说明

日期：2026-11-04。本文对应已经落地的页面和组件，不是静态原型。看板使用实际扫描结果或经过运行时校验的导入JSON；没有加入示意业务数据，也没有新增任何执行上传Skill的能力。

## 1. 阅读目标与信息层级

报告应先回答“本次结论是什么、哪些证据需要优先看、哪些能力没有测”，再让读者进入文件与行号细节。采用四层结构：

```text
报告标题、版本、状态、导出/重扫/对比操作
└─ 核心看板
   ├─ 决策指挥台：风险脉冲、严重度轨道、已测范围
   ├─ 发布决策 + 风险总览 + 局部质量 + 文件编目
   ├─ 风险分布图          质量覆盖环图与权重
   └─ 能力状态/耗时        Top风险文件或公开分类表
└─ 门禁理由、逐阶段说明与覆盖详情
└─ 证据 / 质量依据 / 文件清单 / 规范来源 / 执行记录
```

核心看板是视觉主角，详细证据继续保留。公开摘要和私有完整报告复用同一布局，但不会把已省略的细节伪装成“没有风险”。

## 2. 视觉系统

保留SQSP的深绿主色，配合偏暖的浅灰背景与白色图表面板。发布阻断使用暗红决策卡，证据不足使用深灰绿，人工审查使用棕金；风险等级另用红/橙/金/蓝/灰编码。颜色同时配有状态文字、数量和图例，不能仅凭颜色理解结论。

视觉采用成熟 B2B 控制台常见的“决策优先、高对比、证据下沉”层级：深色决策指挥台建立第一视线，白色数据面板承接审查细节。大数字只用于有真实数据的KPI；小字号英文编号区分图表分区，中文标题承担主要阅读。图表采用原生SVG/CSS，不增加大型图表库，不加载外部图片、字体或报告内嵌图像。环图、风险条与耗时条具有明确的文本解释；装饰不参与评分。

## 3. 图像与表格的具体设计

| 组件 | 数据与计算 | 视觉/交互 | 语义边界 |
|---|---|---|---|
| 决策指挥台 | `scan.status`、`security_risk_index`、finding等级计数、已完成阶段与质量覆盖 | 深色网格底、风险脉冲环、五条严重度轨道、最小事实标签 | 风险脉冲严格标记为“仅用于审阅排序”；状态感知动画可被`prefers-reduced-motion`关闭，不能代表实时监控或新增检测 |
| 发布决策卡 | `scan.release_decision`、策略版本 | 大色块标题，保留BLOCK/INCOMPLETE/REVIEW/ALLOW原枚举 | ALLOW只指当前配置门禁，不是安全认证；导入报告标为“报告声明的发布决策” |
| 风险/质量/文件KPI | 完整finding计数、`quality.static_subscore`、`artifact.files` | 四列摘要区，数字+解释 | 局部分与完整质量分分开；null显示未评测；公开摘要不补造文件清单/大小 |
| 风险等级堆叠条 | `security.finding_counts`，各等级占总finding数比例 | SVG横条+五个带数字的图例按钮 | 条形表示发现分布，不是安全分；0条仍明确“不代表无风险” |
| 质量覆盖环图 | `quality.coverage` | SVG圆环与灰色未完成区域 | 40%是已完成维度权重，不是质量40分或安全通过率40% |
| 四维权重图 | 四维固定20/20/40/20及原始score/status | 细条权重、已测绿色/未测斜纹、每维标签 | 未测项不赋0或100，不把已测部分重归一化成完整分 |
| 检测能力矩阵 | `scan.stages` | 六阶段状态格，已完成/发现/部分/不可用/错误分别着色并显示文本 | PARTIAL/ERROR/TIMEOUT/UNAVAILABLE不计为完整通过 |
| 阶段耗时柱图 | 已运行且有记录的`duration_ms` | 与最大已记录时长相对的水平条，旁边标ms | 未运行项显示“未测”，缺失显示“未记录”；合计不含排队，不是宿主任务延迟 |
| Top风险文件表 | 按严重+高风险数、总发现数排序前5 | 文件位置、密度条、高风险数、总数、分类数 | 密度仅描述证据集中位置；未命中文件可能有规则盲区 |
| 公开风险分类表 | 聚合摘要category计数前5 | 分类、计数与占比小条 | 不含文件路径与证据，因此不提供文件定位；缺失细节不等于清洁 |
| 质量检查依据表 | 检查点、类别、passed、evidence_ref | 取代原始JSON，支持折叠查看 | 区分官方必填/官方可选/包内完整性/平台建议，不能混称官方标准 |
| 证据/清单/日志表 | 现有finding、inventory、stage log | 保留分页、展开、筛选、hash和版本 | 源内容仅按纯文本展示，不渲染HTML或执行URL |

等级图例点击后，平台报告页切到“安全发现”标签、清除旧引擎筛选、重置分页并滚动到对应证据；当前等级保留可见选中态。看板使用完整报告的计数，而不是当前分页的20条数据，筛选不会把总体风险分布误改为局部样本。

## 4. 三个使用入口

| 入口 | 数据来源 | 提供能力 | 不做什么 |
|---|---|---|---|
| 原平台 `/scans/:id` | 当前API与真实Worker结果 | 核心看板、证据、质量表、导出、重扫、版本比较 | 不改变扫描/评分/门禁语义 |
| 平台内 `/viewer` | 浏览器选择已有JSON | 本地看板、证据筛选、聚合摘要下载 | 不调用扫描API、不上传报告、不存浏览器持久历史 |
| 独立`build:report`产物 | 本地JSON，或发布者打包的聚合摘要 | 无后端的查看器；或打开即显示同份聚合摘要 | 不轮询health/API，不创建新扫描，不证明报告真实执行 |

独立构建使用 `frontend/report-site/index.html` 和 `report-main.tsx`，不加载完整平台路由或API健康轮询。CSP包含 `connect-src 'none'`；用户文件只在当前页面内存处理，不写入URL、localStorage或IndexedDB。页面加载本站静态JS/CSS是正常网络访问，这与“报告不上传”分别说明。

本地导入和内置摘要始终显示“未经平台验签”。JSON里的BLOCK/PASS/质量分属于输入文件声明；运行时结构校验只能确认格式及内部统计一致，不能证明扫描来源或结果真实性。

## 5. 实际代码结构

```text
frontend/src/pages/ReportPage.tsx
  ├─ API/轮询/导出/重扫/筛选状态
  ├─ ReportBoard
  ├─ QualityChecks（依据表）
  └─ 原有详细报告Tabs
frontend/src/components/report/
  ├─ ReportBoard.tsx        纯展示与选择回调，无网络请求
  └─ report.css            看板、图表、响应式及打印样式
frontend/src/pages/ReportViewer.tsx
  ├─ 本地File读取、错误与清空状态
  ├─ 未验签提示、ReportBoard复用
  └─ 本地证据/聚合规则计数、摘要下载
frontend/src/reports/localReport.ts
  ├─ 5MiB/树深度/数组数量/枚举/数值校验
  ├─ 完整报告与sqsp-public-1.0摘要解析
  └─ 允许列表投影与已知密钥样式遮盖
frontend/report-site/index.html + src/report-main.tsx
frontend/vite.report.config.ts -> frontend/dist-report
scripts/build_report_site.py -> release/<新目录>
```

核心组件接受`report`和`scan`数据，额外通过`selectedSeverity`显示平台页面的筛选状态、`detailVisibility`选择完整/聚合模式、`aggregates`接收类别/规则计数、`provenanceMode`区分平台结果与导入声明。`onSeveritySelect`只是选择回调，组件自身不发送请求。平台与独立查看器因此可共享看板，不复制一套统计逻辑。

## 6. 公共摘要与打包边界

`sqsp-public-1.0`只保留固定枚举和实际数值：扫描状态、文件数、风险指数、severity/category/rule计数、阶段状态/耗时、质量原值和发布决策。原始名称、标识、hash、路径、证据、context、权限、日志、任意reason以及规则集/策略版本均不进入公开包。

聚合模式改为分类/规则计数，不伪造finding证据。未披露的版本显示“未披露”。`scripts/build_report_site.py`从允许字段重建数据树，将摘要放在转义后的`application/json`段，拒绝已存在的输出目录和构建目录重叠；只打包受限静态资源，永不覆盖或自动发布。

聚合不等于保证匿名。罕见风险组合、数量和阶段耗时仍可能透露业务活动。作者应先用静态HTTP在本地预览，确认愿意披露统计，再上传新release目录；不发布原仓库、原ZIP或完整私有JSON。操作步骤与托管成本见[上线评估](PUBLIC_DEPLOYMENT_ASSESSMENT.md)。

## 7. 小屏、可访问性与打印

摘要区在1100px以下由四列改为两列；780px以下图表区单列；460px以下进一步压缩图例、圆环和面板间距。表格局部横向滚动，文件名允许断行，避免长路径撑破布局。

SVG图表含`role="img"`、`title`或`aria-label`；表格含caption和行/列语义；风险图例是有名称的button，支持键盘焦点，不以颜色作为唯一信息。公开摘要没有可定位证据时禁用等级选择。`prefers-reduced-motion`关闭过渡，打印样式尽量避免卡片被分页拆断。

这些是本轮实现的布局和语义规则，不等同于完成完整WCAG审计；实际桌面/小屏浏览器截图及测试数字应由最终验收记录说明。
