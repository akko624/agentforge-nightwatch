# 面向他人的可分享产物

报告本身包含风险结论、版本、文件路径甚至证据上下文；因此“方便分享”和“公开原始结果”不是一回事。推荐按接收者、数据敏感度和互动需求选择下列产物。

| 产物 | 适合对象 | 使用门槛 | 可公开性 | 推荐度 |
|---|---|---:|---|---:|
| 固定聚合看板（静态链接） | 客户、面试官、评审会、作品集读者 | 点开链接 | 仅复核过统计摘要后可公开 | 首选 |
| 浏览器本地报告查看器（ZIP） | 同事、内审、客户安全团队 | 解压后用浏览器打开或静态托管 | 不上传报告；数据只留在对方浏览器内存 | 首选 |
| 完整 JSON + 本地查看器 | 有权限的工程/安全评审者 | 需要安全传输与内部权限 | 不公开 | 内部协作 |
| 可复现演示包（合成 Skill ZIP + 静态报告） | 销售演示、培训、技术交流 | 点开看板或本地导入 | 可以公开，但仅限合成样例 | 推荐 |
| 本地 Skill / CLI 封装 | 经常要扫描的人 | 安装一次、在自己电脑运行 | 结果不离开本机；发布前仍需审计该封装 | 适合重复使用 |

## 最适合快速分享的两种形式

### 1. 固定聚合看板：一条公共链接

这是最接近“别人点开立刻懂”的产物。执行以下命令会从完整报告重新构造一份允许字段清单，只将统计值嵌入静态页面：

```powershell
.\.venv\Scripts\python scripts/build_report_site.py --report path/to/report.json --output release/my-public-report
```

将新生成目录上传到任意静态站点服务即可；不需要数据库、API 或扫描 Worker。该项目已经有可上传的合成示例包 [sqsp-report-dashboard.zip](../release/sqsp-report-dashboard.zip)。

公开摘要刻意不含 Skill 名称、扫描 ID、文件路径、哈希、代码片段、权限、日志、规则/策略版本或自由文本原因。它仍是发布者提供的、未经平台验签的统计快照，不代表认证结论；罕见的风险分布和耗时也可能泄露业务活动，应先本地预览。

### 2. 本地查看器：让对方带着自己的 JSON 使用

```powershell
Set-Location frontend
npm run build:report
Set-Location ..
.\.venv\Scripts\python scripts/build_report_site.py --output release/my-report-viewer
```

把 `release/my-report-viewer` 压缩发送给对方，或只托管这个工具页面。对方选择 JSON 后，解析、过滤和渲染都在浏览器内存完成：页面 CSP 禁止向外连接，且不写 `localStorage`、`sessionStorage`、IndexedDB 或 URL。这样适合安全评审：页面可以共享，报告文件仍由收件人自行保管。

## 分享前的最小检查清单

1. 公开场景只发固定聚合包或合成演示包；不要把原始 ZIP、完整 JSON、数据库、`data/` 或整个仓库上传到静态站点。
2. 打开生成目录确认没有路径、凭据、客户名、hash、代码片段和不应公开的统计组合。
3. 对外文案使用“本次静态扫描结果 / 已测范围”，不要写成“已安全认证”。
4. 需要撤回、访问控制、到期、下载审计时，改用带身份认证和 TTL 的受控分享，而不是试图撤回已被缓存或下载的静态链接。
5. 若接收者需要自己反复扫描，把可信的扫描器封装为本地 Skill/CLI；目标 Skill 仍只能作为数据读取，不能因为打包成插件就执行它。

## 视觉设计原则

当前报告使用“安全运营指挥台”而不是营销大屏：高对比的决策区提供第一眼结论，风险脉冲、分布轨道和阶段矩阵帮助扫读，随后才进入可审查的表格证据。设计取向参考成熟 B2B 控制台常见的清晰信息层级、紧凑数据密度与强状态对比；实现仍复用 Ant Design，并以原生 CSS/SVG 渲染，不新增外部字体、图表 CDN 或遥测。

风险脉冲中的指数仅用于审阅排序，覆盖环仅表示已测质量权重；两者都不等同于通过率、质量分或安全认证。动画只作为轻量状态感知，系统启用“减少动态效果”时会关闭。

有关公共访问的服务选择、存储边界与成本估算，见 [PUBLIC_DEPLOYMENT_ASSESSMENT.md](PUBLIC_DEPLOYMENT_ASSESSMENT.md)。
