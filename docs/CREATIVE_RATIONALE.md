# SkillForge NightWatch：创作思路与产品演进

## 一句话定位

**SkillForge NightWatch 面向 Agent Skill 提供安全摄入、证据归集、发布门禁与改进建议；它把可并行的非交互审计放入合适的低峰时段，让开发者和 Agent 在需要时获得可复核的结论。**

“NightWatch”不是把夜间作为噱头，而是对一种工作方式的描述：安全检查、版本比较和改进简报通常不要求用户在线等待，可以由队列在低负载时逐步处理。这样能更充分利用夜间可用算力，同时保留白天快速查看结果、审查证据和决定下一步的体验。

## 创作原则

### 1. 让算力花在值得运行的候选上

所有上传包先经过零执行的结构与静态检查。只有风险、覆盖、版本变化和人工批准共同指向需要深入验证的候选，才应进入未来的受控隔离评测。低峰批处理提升的是编排效率，不是“运行更多不可信代码”。

```text
上传 Skill
  -> 零执行的快速结构/静态扫描（所有包）
  -> 风险、覆盖与版本变化驱动的优先级队列（选中包）
  -> 获批隔离环境中的真实评测（未来能力，仅白名单候选）
```

### 2. 让结果在白天可被复核和使用

队列的价值不止是异步完成任务，还要把执行结果变成可理解的工作材料：风险证据、阶段状态、质量覆盖、版本差异和 P0/P1/P2 改进路线应在同一份报告中关联呈现。改进建议只提供可审查的下一步，不会自动写回 Skill。

### 3. 不用虚构指标换取叙事完整性

当前可以展示任务状态、阶段耗时、规则分布、质量覆盖、版本差异和合成样例的修复前后对比。GPU 利用率、真实模型成本、动态命中率和漏洞库覆盖率尚无可审计数据时，不应写成实测结论；应在具备隔离 Runner、指标采集和基线后再展示真实数据。

## 已实现的产品闭环

| 环节 | 已实现事实 | 给使用者的价值 |
|---|---|---|
| 安全摄入 | ZIP 限额、路径/链接拒绝、内容寻址工件；不执行上传内容 | 安全地接收候选 Skill |
| 异步编排 | API 与独立 Worker 分离；任务有租约、重试与恢复 | 适合批量和低峰任务处理 |
| 可解释扫描 | 版本化 S001–S016、schema、权限交集、质量覆盖与门禁 | 每个结论均可追溯 |
| 决策看板 | 风险分布、覆盖、阶段矩阵、版本对比、静态分享 | 快速理解当前状态与变化 |
| 改进工作台 | 依据真实报告生成 P0/P1/P2 路线和 Markdown 简报 | 将发现问题转成可审查的改进闭环 |
| Agent 接入 | `skillforge-nightwatch` 安装包安全调用本机平台 | 让其他 Agent 可开箱使用 |

动态沙箱、模型评测、真实宿主正确性和漏洞情报当前不具备时会显示 `UNAVAILABLE` 或 `NOT_RUN`。这些是可信边界，而不是需要用替代实现掩盖的缺口。

## 三分钟产品演示

1. **问题。** Agent Skill 越来越多，但直接执行不可信 Skill 可能泄露凭据，也会浪费有限算力。
2. **安全入口。** 上传合成疑似风险包，说明 API/Worker 分离以及上传代码不执行。
3. **证据看板。** 展示风险脉冲、覆盖缺口与阶段矩阵；点击 HIGH 进入具体证据。
4. **演进建议。** 打开“Skill 改进工作台”，导出 P0/P1/P2 简报；强调建议不是自动修复。
5. **规模与共享。** 展示版本对比、公共聚合摘要和 Agent Skill 包；说明低峰批处理会作为受预算约束的路线能力演进。

## 下一轮实现优先级

| 优先级 | 能力 | 产品价值 | 必要前置 |
|---|---|---|---|
| P0 | 低峰批处理：定时批次、并发/成本预算、队列看板 | 让闲置时段算力被可解释地利用 | 任务调度、租户/配额、审计日志 |
| P0 | 指标采集：队列等待、CPU/内存/耗时、规则耗时 | 用真实数据优化编排和容量 | 隐私化遥测、基线、仪表板 |
| P1 | 补丁审阅台：候选 diff、验证结果与人工批准 | 将建议变成可控的改进闭环 | 补丁隔离、版本控制、确认机制 |
| P1 | 真实隔离 Runner 与评测集 | 支持经批准的正确性/稳定性测量 | 无凭据隔离、网络/文件策略、回收与配额 |
| P2 | 团队/多租户、分享链接生命周期 | 从个人工具走向协作产品 | 身份、授权、TTL、对象存储 |

## 对外表达建议

- 名称：**SkillForge NightWatch**；副标题可用 **“持续守护，持续进化”**。
- 叙事从真实工作流出发：夜间或低峰时段处理不需要即时交互的审计，白天以报告和证据支持决策。
- 演示只使用仓库中的合成样例；不要公开客户 Skill、凭据、完整报告或本机数据。
- 架构说明突出“未可信 Skill 不执行”与“快速静态层 → 受控隔离层”的双层原则。
- 将低峰批处理、真实隔离 Runner 和指标采集明确标注为路线能力，不将其写成已经上线的功能。
