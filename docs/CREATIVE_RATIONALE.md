# SkillForge NightWatch：创作思路与产品演进

## 一句话定位

**SkillForge NightWatch 面向带 `SKILL.md` 的 Skill ZIP 提供安全读取、证据归集、发布门禁与改进建议，让开发者和 Agent 获得可复核、可比较的工程结论。**

“NightWatch”表达的是持续守护：检查不代替人做发布决定，却能让每个决定都有证据、范围与边界。安全扫描、版本比较和改进简报由独立 Worker 异步处理，开发者可在需要时回到看板审查结果并决定下一步。

## 创作原则

### 1. 让验证资源花在值得深入审查的候选上

所有上传包先经过零执行的结构与静态检查。平台将风险、覆盖和版本变化组织为可审查的证据，再把发现转为清晰的整改优先级与下一版 Skill 的输入。

```text
上传 Skill
  -> 零执行的快速结构/静态扫描（所有包）
  -> 风险、覆盖与版本变化驱动的审查优先级
  -> 改进建议、候选版本与重新扫描对比
```

### 2. 让结果随时可被复核和使用

队列的价值不止是异步完成任务，还要把执行结果变成可理解的工作材料：风险证据、阶段状态、质量覆盖、版本差异和 P0/P1/P2 改进路线应在同一份报告中关联呈现。改进建议只提供可审查的下一步，不会自动写回 Skill。

### 3. 不用虚构指标换取叙事完整性

当前可以展示任务状态、阶段耗时、规则分布、质量覆盖、版本差异和合成样例的修复前后对比。GPU 利用率、真实模型成本、动态命中率和漏洞库覆盖率尚无可审计数据时，不应写成实测结论；应在具备隔离 Runner、指标采集和基线后再展示真实数据。

## 已实现的产品闭环

| 环节 | 已实现事实 | 给使用者的价值 |
|---|---|---|
| 安全摄入 | ZIP 限额、路径/链接拒绝、内容寻址工件；不执行上传内容 | 安全地接收候选 Skill |
| 异步编排 | API 与独立 Worker 分离；任务有租约、重试与恢复 | 适合批量、长耗时和可恢复任务处理 |
| 可解释扫描 | 版本化 S001–S016、schema、权限交集、质量覆盖与门禁 | 每个结论均可追溯 |
| 决策看板 | 风险分布、覆盖、阶段矩阵、版本对比、静态分享 | 快速理解当前状态与变化 |
| 改进工作台 | 依据真实报告生成 P0/P1/P2 路线和 Markdown 简报 | 将发现问题转成可审查的改进闭环 |
| Agent 接入 | `skillforge-nightwatch` 安装包安全调用本机平台 | 让其他 Agent 可开箱使用 |

## 三分钟产品演示

1. **问题。** Skill 包越来越多，但直接执行不可信 Skill 可能泄露凭据并扩大宿主风险。
2. **安全入口。** 上传合成疑似风险包，说明 API/Worker 分离以及上传代码不执行。
3. **证据看板。** 展示风险脉冲、覆盖缺口与阶段矩阵；点击 HIGH 进入具体证据。
4. **演进建议。** 打开“Skill 改进工作台”，导出 P0/P1/P2 简报；强调建议不是自动修复。
5. **规模与共享。** 展示版本对比、公共聚合摘要和 Skill 包，说明报告如何在不暴露代码与证据细节的前提下分享结论。

## 对外表达建议

- 名称：**SkillForge NightWatch**；副标题可用 **“持续守护，持续进化”**。
- 叙事从真实工作流出发：独立 Worker 异步处理审计，开发者通过报告与证据支持发布决策。
- 演示只使用仓库中的合成样例；不要公开客户 Skill、凭据、完整报告或本机数据。
- 架构说明突出“未可信 Skill 不执行”与“快速静态层 → 受控隔离层”的双层原则。
