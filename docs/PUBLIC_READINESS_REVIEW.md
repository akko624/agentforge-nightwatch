# 公共访问与无后端报告查看器：代码就绪度评估

核验日期：2026-11-03。依据为当前仓库实际代码；这是上线架构审查，未进行公网攻击测试，也未部署公共站点。以下 P1 / P2 以“向不互信的公众开放”为前提。当前本机单用户、回环监听的使用方式已有明确边界，这些结论不表示当前本机部署已经发生泄露。

## 建议先发布什么

先发布**静态报告查看器**，让访问者在浏览器内选择本地报告 JSON。扫描继续在作者的本机或受控服务运行。公开页面不连接扫描 API、不接收 ZIP、不保存访客报告，能以较小改造获得公共链接，同时保留现有 Python 规则和独立 Worker 的边界。

另一个需求是“只发链接，对方直接看到同一份报告”。这必须把某个报告副本提供给对方：可将审核后的公开摘要作为静态文件随站点发布，或放在公开对象存储中。**不需要数据库**，但内容仍由静态托管商保存、分发；不能称为“没有服务端存储”。仅有本地 JSON 查看器时，公共链接只能分享工具，对方仍需拿到报告文件。

当前完整平台适合继续作为受控扫描端。将它的 API 直接改成公网监听，不是静态托管意义上的简单上线。

## 查看器的最小安全契约

建议区分两种格式和两种提示，避免将“能渲染”误写成“平台已验证”：

| 输入 | 用途 | 页面必须说明 |
|---|---|---|
| 完整 SQSP JSON 报告 | 本人在浏览器内查看已有本地报告，保留证据细节 | 文件仅在本页内存处理；文件内容属于用户提供的检测声明；未验证来源、真实性或签名；已知密钥样式的脱敏不能替代人工检查 |
| `sqsp-public-summary-1` 摘要 | 作者审核后发布、共享或下载的最小副本 | 源证据与路径已省略；结论仅转述摘要；不可据此还原原报告或保证 Skill 安全；公开后对方可能留存副本 |

查看器应采用以下具体约束：

1. 读取前检查文件大小。建议初始 JSON 上限 5 MiB；这与扫描端 20 MiB ZIP 限额是两个不同限制。大小上限仍不能完全避免主线程阻塞，文件数量与深度也应限额，较大输入放入专用 Web Worker 解析。
2. 解析后验证根对象、明确版本、字段类型和枚举。限制深度，例如不超过 20；限制 findings，例如不超过 2,000；文件清单不超过 300；每个字符串与动态数组有独立上限。拒绝非有限数字、负数量和 0–100 以外分数、0–1 以外覆盖率；不静默把错误值变成 0。
3. 只投影明确允许的字段，不将 JSON 合并到组件配置、样式、对象原型或执行参数中。忽略或拒绝未知版本；可拒绝 `__proto__`、`constructor`、`prototype` 等危险键。`JSON.parse` 本身不执行脚本，但后续无约束对象合并可能引入问题。
4. 不通过 HTML / Markdown 插入源内容，不使用 `eval`、动态 import、data URL、上传包脚本或远程资源。SVG 图表由本地组件按验证后的数值绘制，不嵌入报告自带的 SVG / 图片 / CSS。
5. 报告中出现的 URL 只按纯文本展示；不自动获取“附件”“规则更新”“来源证明”或共享链接。下载对象 URL 只能指向当前浏览器新生成的 JSON Blob，使用固定文件名并及时回收。
6. 不把原报告内容写入 URL、localStorage、IndexedDB、Service Worker 缓存或分析 / 错误上报。不要把报告值当成 DOM 属性、日志、追踪事件名称或页面标题。选新文件、清空和退出时释放引用；浏览器扩展、截图、系统交换内存等不在此承诺的控制范围内。
7. 空值、未运行和部分完成继续显式展示。不能把未运行维度渲染为满分，也不能用部分维度重归一化出完整质量分。导入 JSON 的 PASS / ALLOW 是文件中的声明，未经可信签名验证不能显示为平台认证徽章。
8. 发布前用开发者工具验证本地导入时没有携带报告数据的请求；自动化测试应把 fetch / XHR / sendBeacon 调用作为检查对象。静态页面加载 JS / CSS 请求是正常资源访问，不能笼统承诺“浏览器完全无网络”。

这些是本次查看器的验收建议。具体哪些已落实，应以本轮代码与测试结果为准；本审查不提前把新增功能计为完成。

## 可实施的最小公开摘要

可采用下面的 schema 语义；示例只是字段契约，不是伪造检测数据：

```text
schema_version: "sqsp-public-summary-1"
display_title: 固定的“Skill 检查摘要”，或作者明确审核后的发布标题
summary_status: 扫描状态枚举
security:
  verdict: PASS | REVIEW | BLOCK | UNKNOWN
  severity_counts: INFO / LOW / MEDIUM / HIGH / CRITICAL 的非负整数
  rule_counts: [{ rule_id: 已知 SQSP 规则 ID, count: 非负整数 }]
quality:
  score: number | null
  coverage: 0..1
  static_subscore: number | null
  dimensions: [{ dimension: 已知维度枚举, weight: 0..1,
                 status: 阶段状态枚举, score: number | null }]
stages: [{ name: 已知阶段枚举, status: 阶段状态枚举 }]
decision: ALLOW | REVIEW | BLOCK | INCOMPLETE
ruleset_version: 受支持的固定规则版本；未知则显示“未识别”
publication_notice: 页面程序固定文案，不从源报告复制
```

标题不应默认继承 Skill 名称；公开摘要无需原 scan_id、skill_id、version_id、工件 / 文件 / 指纹 / 源码 hash、owner_label、文件名、manifest、证据、context_note、remediation、reason、权限路径、policy_snapshot、日志或精确创建时间。规则名称与通用修复建议可从平台自己固定的规则目录读取，不能复制源报告中同名字段的自由文本。

如需“高风险文件 Top N”图表，可用本次摘要内的 `文件 01`、`文件 02` 展示聚合计数，映射只在本地内存存在，不导出原路径、不用原路径 hash 充当匿名 ID。类别未知时归入固定的“其他”，不回显未知类别原字符串。摘要导出必须以字段允许清单重新构造新对象；“从完整对象删掉几个字段”容易在后续新增字段时意外公开。

数字、规则组合和罕见时间也可能关联业务活动，因此“已省略敏感字段”比“已完全匿名 / 绝无隐私风险”更准确。公开文件一经访问，托管侧撤销只能阻止未来访问，不能收回下载和浏览器缓存的副本。

## 后端存储可以省掉到什么程度

| 架构 | 服务端要保存什么 | 可保留能力 | 取舍 |
|---|---|---|---|
| 静态查看器 + 本地 JSON | 仅查看器静态资源；访客 JSON 不主动上传 | 看板、证据筛选、图表、本地导出 | 不能替访客运行现有 Python 扫描器；链接不包含本地文件 |
| 静态站点内置经审核摘要 | 静态资源与公开摘要副本 | 直接链接打开指定报告 | 不需要数据库，但确有托管存储；版本更新 / 撤销依赖重新发布与缓存策略 |
| 临时扫描后端 | 请求内存或临时盘、临时任务状态；可有 TTL 对象与队列 | 保留现有 Python 规则，并返回报告下载 | “不永久保存”不等于“没有后端”。重启、断线、后台任务恢复、重复检测与历史比较要重新定义；多实例不能依赖彼此看不见的本地临时盘 |
| 完整持久扫描平台 | 私有 ZIP、数据库状态、报告、队列、公开快照 | 异步任务恢复、审计、版本比较、分享和撤销 | 运维与权限成本最高；持久副本、备份与保留期都需治理 |

当前 `orchestrator.py:24–55` 的任务领取 / 租约恢复依赖持久 SQL 状态，`:141` 依赖已保存的 ZIP，`:189–201` 持久保存结果；直接移除数据库和工件目录会破坏这些能力。若改成同步临时任务，应另设受限服务契约、超时和容量模型，不能仅把已有目录改成 `/tmp` 就宣称无存储架构完成。

## 纯前端扫描与云端边缘运行的边界

现有 S003 / S001 等依赖 Python `ast.parse`、本地别名与局部数据流（`backend/app/scan/static_rules/builtin.py:222–230`）；导入还使用 Python zipfile / YAML / JSON Schema。将 Vite 前端部署到静态站点不会顺便部署这些 Python 能力。

浏览器路线可选把解析器与规则移植到 JavaScript / WASM，或引入受控 Python WASM 运行时。前者需要重做并比较规则等价性；后者有下载体积、内存、性能和依赖兼容成本。无论哪种，上传文件仍只能作为待分析数据，不能在解释器里执行上传 Python、shell 或 Skill 指令，也不能用不可信文件名覆盖运行时自身模块。ZIP / YAML 安全配额、Python AST、依赖覆盖、脱敏、稳定指纹和版本比较都要重新验收，不能继续沿用本机 Python 的“200 测试通过”作为浏览器扫描证据。

类似 Workers 的请求隔离运行时与当前 FastAPI + Redis / RQ 常驻 Worker 部署模型不同。能托管静态看板、边缘路由或对象分发，不等于无需改造就能运行当前 Python 服务。现有 Worker 至少可持有整个解压包、UTF-8 文本、按行副本和 AST（`builtin.py:132–172`），不能只按 ZIP 压缩体积估算内存。具体云服务内存 / CPU / 包大小限制应按其当前官方文档逐项核验。

## 上线验收顺序

1. 静态查看器：运行时 JSON 校验、大小与数组限额、纯文本渲染、无报告出站请求、无持久浏览器缓存、未知来源声明和完整 / 局部分数区分。
2. 审核后摘要链接：允许清单导出、发布预览、独立托管目录、缓存 / 替换 / 撤销说明，确认部署包不带 data、原 ZIP、测试私有样本、.env 或 source map 中的实际报告。
3. 受控扫描服务：先在 Linux 验证 PostgreSQL / Redis / RQ 及容器流程，再完成认证、所有权、速率 / 并发 / 总量配额、保留期、备份恢复和运行监控。匿名扫描需要额外的滥用与预算控制。

不建议为了本次报告分享需求先把完整匿名上传平台上线。先以静态查看器或经审核的摘要快照验证实际使用，再决定是否为历史、多人协作和在线扫描支付后端成本。

## 本轮实现后的有界复核

本轮新增了 `frontend/src/reports/localReport.ts`、`pages/ReportViewer.tsx`、`report-main.tsx`、`frontend/report-site/index.html`、`vite.report.config.ts` 和 `scripts/build_report_site.py`。复核仅针对这些新边界，没有把前文已知的私有扫描端认证缺口重复列为新增问题。

已确认的实现边界：独立页面不挂载平台 App 或健康轮询，静态配置禁用 publicDir，页面和打包头部设置 `connect-src 'none'`；公开导出以允许清单重新构造对象，不复制原名称、ID、路径、证据、hash、权限、日志等源自由文本；打包器拒绝现存输出目录、构建目录重叠、符号链接和非 index / assets 文件。页面明确标注导入文件未验签，聚合模式不会把未提供的原文证据解释为零发现。

本次有界复核反馈并修正了四项数据完整性 / 资源问题：

| 问题 | 修正后的边界 |
|---|---|
| 无已测静态维度仍可带非空 static_subscore | 局部静态分必须有两个已测静态维度作为前提，并与维度得分一致；未测时保留 null |
| 导入聚合阶段缺失耗时被补为 0 ms | 缺失记录直接拒绝，不伪造已测零耗时；未运行项在看板标为未测 |
| 浏览器与 Python 对重复 JSON 字段处理不一致 | 浏览器解析前拒绝重复字段，包含 JSON 转义后的同名键；Python 输入同样拒绝重复字段 |
| 数组 / 总节点在完整 JSON 分配后才被限制 | 解析前词法检查深度 20、数组 2,500 项和总节点 80,000，解析后仍做结构复核；遍历数组先检查 length，再生成 entries |

独立回归文件为 `frontend/tests/public-review.test.ts` 与 `backend/tests/test_public_review.py`。最终修复后的相关导入 / 查看器 / 复核用例 12 项、公开导出 / 打包用例 6 项通过；全套构建与测试的最终数字以本轮交付记录为准。上述结果验证的是输入边界和程序行为，不是报告真实性、绝对匿名或已完成公网部署的证明。
