# 公共访问就绪度审查

## 适合公开的范围

当前可公开的是静态报告查看器和经过作者审核的脱敏摘要。它们不连接扫描 API、不接收 ZIP、不保存访客上传内容，也不执行任何 Skill 代码。完整本地平台默认只监听 `127.0.0.1`，且没有认证、资源所有权或多租户边界，不能直接暴露为匿名上传服务。

## 静态查看器最低安全契约

- 仅接受报告 JSON，读取后先做大小、结构、枚举、深度和数组数量校验。
- 只投影明确允许字段；拒绝危险原型键和未知 schema 版本。
- 所有报告内容使用纯文本渲染；不使用 HTML 注入、`eval`、动态 import、远程报告资源或上传文件脚本。
- 本地查看模式不把报告写入 URL、localStorage、IndexedDB、Service Worker 缓存、分析或错误上报。
- 明确显示“用户提供、未验签”；`ALLOW`、质量分或 PASS 只是报告内的声明，不是公共站点再次认证。
- `null`、`NOT_RUN`、`UNAVAILABLE` 与局部覆盖必须原样展示，不能图表化为满分或零风险。

## 摘要发布前检查

1. 通过允许清单重新构造摘要，不从完整报告做“删除几个字段”的反向过滤。
2. 默认移除工件 / 扫描 / 版本 ID、原名称、路径、hash、manifest、文件清单、证据、权限、策略快照和日志。
3. 检查构建目录中没有数据库、原 ZIP、`.env`、私有报告或 source map 泄露。
4. 用真实公网链接检查匿名可达、缓存 / 替换说明、响应头和移动端显示。

## 未来在线扫描的前置条件

若要让不互信用户在线上传，需先新增身份认证、每条资源所有权校验、速率 / 并发 / 队列 / 存储配额、保留期和可审计删除、备份恢复、监控告警与滥用响应。还要把 SQLite 本地单用户存储替换为适合多用户、受访问控制的持久化方案。动态扫描仍须使用单独验证过的隔离运行器；不得因上线便利而执行上传代码。
