# SkillForge NightWatch：夜间算力大赛参赛叙事与产品路线

> 本文不宣称已获得主办方的具体赛题或评分细则。公开检索未获得可核验的“夜间算力大赛”规则页；提交前应以报名页、赛题书和官方 FAQ 校对赛道名称、评审维度、数据合规与演示时长。

## 一句话定位

**SkillForge NightWatch 是面向 Agent Skill 的“夜间守夜人”：在低峰时段完成安全与质量证据归集，白天把可复核的发布决策与改进简报交给开发者和 Agent。**

这比“又一个聊天助手”更贴合算力主题：将可并行、非交互的 Skill 审计移到低峰批处理队列；把高成本的真实宿主/模型评测留给通过静态门禁且经人工批准的候选，而不是对所有上传包盲目运行。

## 已经可以演示的闭环

| 环节 | 已实现事实 | 演示价值 |
|---|---|---|
| 安全摄入 | ZIP 限额、路径/链接拒绝、内容寻址工件；不执行上传内容 | 回答“为什么能安全接收 Agent Skill” |
| 异步编排 | API 与独立 Worker 分离；任务有租约、重试与恢复 | 回答“为什么适合批量/夜间作业” |
| 可解释扫描 | 版本化 S001–S016、schema、权限交集、质量覆盖与门禁 | 回答“结论从哪里来” |
| 决策看板 | 风险分布、覆盖、阶段矩阵、版本对比、静态分享 | 回答“结果如何被人快速使用” |
| 改进工作台 | 依据真实报告生成 P0/P1/P2 路线和 Markdown 简报 | 回答“扫描后如何促进 Skill 进化” |
| Agent 接入 | `skillforge-nightwatch` 安装包安全调用本机平台 | 回答“如何让其他 Agent 开箱使用” |

动态沙箱、模型评测、真实宿主正确性和漏洞情报当前不具备时会显示 `UNAVAILABLE` 或 `NOT_RUN`；这应在答辩中作为可信边界，而不是包装成已实现能力。

## 建议的赛题扣题结构

### 1. 夜间：按风险与成本分层编排

把任务分为三层，而不是一股脑消耗算力：

```text
上传 Skill
  -> 零执行的快速结构/静态扫描（所有包）
  -> 高风险、低覆盖、版本变化的优先级队列（选中包）
  -> 获批隔离环境中的真实评测（未来能力，仅白名单候选）
```

答辩重点是“**算力被用在值得运行的候选上**”：静态层可以大规模并发，运行时层必须受配额、策略和隔离约束。不要把“运行更多不可信代码”表达成创新。

### 2. 白天：证据驱动的 Skill 进化

新增的改进工作台可直接演示：风险先于体验、覆盖先于总分、建议可导出给开发者/Agent，但不自动写回。这样将“发现问题”落到“可审查的改进闭环”。

### 3. 评审指标：可量化且不造数

当前可展示：

- 队列任务状态、阶段耗时、风险/规则分布、质量覆盖与版本差异；
- 同一个合成 Skill 的修复前后对比；
- Agent 包从本机提交 ZIP 到生成报告的端到端流程；
- 完整报告与脱敏聚合看板的不同分享边界。

暂不能展示成实测指标：GPU 利用率、真实任务成功率、模型 token 成本、动态检测命中率、漏洞库覆盖率。若赛题要求这些，先接入可审计采集与真实隔离 Runner，再展示实际数值。

## 三分钟演示脚本

1. **20 秒：问题。** Agent Skill 越来越多，但直接执行不可信 Skill 会泄露凭据或浪费算力。
2. **45 秒：夜间入口。** 上传合成疑似风险包，说明 API/Worker 分离以及上传代码不执行。
3. **55 秒：证据看板。** 展示风险脉冲、覆盖缺口、阶段矩阵；点击 HIGH 进入具体证据。
4. **35 秒：Skill 进化。** 打开“Skill 改进工作台”，导出 P0/P1/P2 简报；强调不是自动修复。
5. **25 秒：规模与共享。** 展示版本对比、公共聚合摘要和 Agent Skill 包。
