# 实现决策

## 本地优先、最小依赖

正式运行路径为 SQLite + SQLAlchemy/Alembic + 独立数据库轮询 Worker。移除了容器、PostgreSQL、Redis、RQ 及其未验证配置，不要求用户安装 Docker 或启动外部服务。SQLite 中的 `scans` 记录是持久化队列；API 只入队，Worker 通过 CAS、租约和有限重试领取任务。

这样减少了首次启动的内存、磁盘、网络和账号前置条件，同时保留了 API 与 Worker 的进程边界。它不是把扫描挪进 API 请求或启动时后台线程；任一进程单独退出时，任务状态仍留在数据库中。

## 只保留真实安全能力

上传内容只经 ZIP、YAML、文本和 AST 处理。动态隔离、模型语义、真实宿主评测与漏洞库接口继续保留，但没有通过可信隔离验证前均返回 `UNAVAILABLE` / `NOT_RUN`。不使用本机子进程、浏览器、普通容器或未知 CLI 执行上传内容。

## 可分享和可公开的边界

完整平台是本机单用户工具，不含认证、RBAC、多租户、配额或生产审计，因此不能直接作为匿名上传服务暴露到公网。公开分享使用脱敏静态报告：报告查看器在浏览器内存读取 JSON，构建的聚合摘要默认移除识别信息与证据。

## 验证原则

只有本仓库实际运行过的 SQLite、独立 Worker、HTTP smoke、自动化测试和前端构建会被声明为已验证。未来如引入动态运行器、远程对象存储或公网上传，必须为该扩展单独设计权限、隔离、配额、保留期和恢复测试，不能由当前本机证据外推。
