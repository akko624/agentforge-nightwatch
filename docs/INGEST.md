# 安全导入与对象存储

ZIP 在 API 中被视为不可信数据。导入只进行受限内存解码，不调用 extract/extractall，
不把 ZIP 条目路径写入磁盘，不 import 或执行 Skill 脚本。Worker 再次读取相同内容寻址
对象并按相同校验流程处理。

在创建 Python ZipFile 和 ZipInfo 对象前，先检查最大上传字节数，并用固定大小 struct
读取 EOCD 和中央目录。既验证声明条目数，也逐记录计算真实条目数；达到配额立即拒绝，
避免攻击者伪造较小 EOCD count 后让标准库先分配数十万个 ZipInfo。
目录边界、记录长度、本地头偏移、多卷和尾随数据也必须通过检查。

当前有意只支持普通单卷 ZIP 的 stored/deflate 方法；ZIP64、多卷、加密、不支持的 Unix
链接元数据、尾随未索引数据会返回 `INVALID_ARCHIVE`，而不会尝试放宽校验。
这一选择不影响当前 20 MiB 上传和 300 条目限额下的正常示例包。

路径校验拒绝绝对路径、驱动器/UNC、反斜杠、点段、空段、ADS、Windows 保留设备名、
尾随点/空格、控制字符、非规范 Unicode 和混淆分隔符，并检查大小写折叠后的重名、
文件与父目录冲突。Unix 类型位和 Windows reparse 位不能声明链接或特殊文件。

默认配额为上传 20 MiB、总展开 100 MiB、单文件 10 MiB、300 条目、路径深度 10、
压缩比 100:1。解压前检查声明大小，解压时再次按实际字节计数。CRC 或结构错误拒绝。
错误细节只有固定原因代码，不包含文件正文、凭据或任意异常堆栈。

文件清单包含相对路径、大小、SHA256、类型、隐藏文件、可执行权限位和是否可解析。
嵌套压缩包和二进制被列出，但不递归执行或展开；其检测覆盖必须由报告明确说明。

## 存储边界

LocalArtifactStore 只接受应用生成的 ASCII key。上传文件名和归档路径不能成为对象 key。
对象写入先落在同目录随机临时文件，flush/fsync 后原子发布；同 key 不同内容拒绝覆盖，
同 key 相同内容幂等。Windows rename 是 create-only；POSIX 使用原子 create-only link。
发布后文件设置为只读。已有路径不能经过符号链接。

这是应用级不可变存储，不是防宿主管理员篡改的 WORM 设施。存储根必须由可信服务独占，
不得允许上传者或其他租户写入父目录；相同 UID 的管理员仍可更改权限。MVP 不声称能抵御
一个已经能并发篡改可信存储目录的宿主攻击者。数据库事务与文件系统不是分布式事务，
进程崩溃可能留下无引用工件；后续清理须先核对数据库引用，不能随意删除持久数据。

## 演示工件

运行 `python scripts/seed_examples.py` 生成 `examples/zips/` 下三个可上传 ZIP：

- `benign-skill.zip`：CSV 报告说明、权限声明、格式文档、模板、许可证和合成 eval 用例。
- `suspicious-skill.zip`：只用于静态检测的合成指令和 Python AST 风险。
- `suspicious-skill-v2.zip`：相同 Skill 名称、版本 1.0.1，只修复 `eval` 风险并保留其余发现。

打包脚本只读取字节，不导入示例。危险函数的首条语句主动抛错，域名使用 `example.invalid`，
示例密钥是明显的合成字符串。它们仍不得交给真实 Agent 执行。测试用例存在不意味着实际
宿主已经运行；动态沙箱和功能/稳定性 Runner 未接入时仍为未运行/不可用。
